# Bridge repository-side release review

This checklist captures the final repository-side review for the Bridge release. It does not replace the manual accessibility walkthrough or the production smoke test against real hosting/TURN infrastructure.

- [x] PR change scope is limited to `bridge/**` plus `.github/workflows/bridge.yml` and `.github/workflows/bridge-deploy.yml`.
- [x] CI and deploy-artifact workflows now enforce the same scope with `scripts/verify-isolation.mjs`; sibling projects and unrelated repository paths fail the check.
- [x] The isolation guard has focused unit coverage for allowed Bridge paths, forbidden sibling/unrelated paths, and misleadingly similar prefixes.
- [x] Both workflows fetch full git history so the isolation check can compare the current branch with its base branch.
- [x] A dependency-free release preflight (`npm run verify:release`) verifies required release/security/runbook artifacts, the reviewed Node 22 package policy, exact top-level dependency versions, required npm reproducibility settings, required validation scripts, required security-header/cache policy values, presence of both Bridge workflow guards, immutable GitHub Action references, read-only workflow token permissions, disabled checkout credential persistence, bounded job timeouts, and deploy-artifact integrity controls before dependency installation.

- [x] Bridge's Node release line is declared as Node 22 and top-level runtime/dev dependency versions are pinned to the reviewed versions rather than floating semver ranges.
- [x] `bridge/.npmrc` explicitly requires package-lock generation, exact saved dependency versions, and strict enforcement of the reviewed Node engine range. The dependency-free release preflight fails if any of these reproducibility controls are removed or relaxed.

Dependency-free `node:test` coverage exercises the origin/URL boundary.

## Scope guard contract

The automated isolation guard allows only paths under `bridge/` and the two Bridge-specific workflow files. It deliberately rejects `colortrace/**`, `extensible-terminal/**`, other root files, and similarly named workflow paths. The guard runs before dependency installation or build steps so an out-of-scope branch fails early.

The release preflight complements that path-level guard. It is intentionally dependency-free and repository-local: it verifies that the reviewed release documentation/security artifacts still exist, package metadata has not drifted from the pinned Node/dependency policy, the production signaling build/runtime manifest contract remains intact, `.npmrc` still requires lockfile generation/exact saves/strict Node-engine enforcement, the baseline security-header file still matches the reviewed policy and cache values exactly, both Bridge workflows continue to invoke isolation plus preflight checks, every external `uses:` reference is pinned to a full commit SHA rather than a mutable tag or branch, workflow token permissions stay read-only, checkout does not persist credentials, job execution remains bounded, and the frontend/signaling SHA-256 manifest generation/verification/upload remain present. It does not claim runtime correctness and therefore cannot replace registry-generated reproducible lockfiles, typecheck/unit/e2e/TURN execution, or the manual release checks.
